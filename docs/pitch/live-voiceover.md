# Local AI on Windows: the advantage that's locked away

**Local AI unlocks a new class of experiences: offline, private, instant, and
free. Windows already ships the on-device HD voices and the hardware to run them.
The one thing missing is the public API to build on. This is the proof, and the
ask.**

> A working reference implementation on top of Windows' on-device Natural (HD)
> voices, built to show Microsoft the public API it should ship. One API,
> local-first and free by default, that scales to Azure with your credentials.

The deck (`live-voiceover.pptx`, generated by `build_deck.py`) follows this same
**Why → What → How** arc.

---

## WHY: Windows is sitting on something groundbreaking

Local AI models unlock scenarios the cloud can't: **offline, private, free,
instant.** On Windows the capability already ships on the box. The *access* does
not.

### Mac proves the model; Windows can take it further

Apple has shipped on-device intelligence to developers for years, so local-first
AI is proven, real, and wanted. Windows already has almost the equivalent on the
box. The opportunity is to go further than Mac can.

- **Apple (proven, but capped):** exposes on-device speech (SpeechAnalyzer),
  on-device neural TTS, and Apple Foundation Models running on the ANE to
  third-party apps. It proves the model, but there's no cloud to graduate to, so
  Apple can't scale you past the device.
- **Windows + Azure (the bigger story):** the same on-device Natural (HD) voices
  are already on the machine, free and offline, and they run on the **CPU of
  virtually any modern PC** (no special NPU required). One API can then scale from
  local to Azure with your credentials, no rewrite. First-party reach across Edge,
  Office, Teams, PowerPoint, and Clipchamp is something no rival can match.

Mac already has almost the equivalent on-device. Only Microsoft can pair it with
Azure and its own product suite, turning a proven idea into a platform advantage.

### The voice is already on the device

- Windows' Natural (HD) voices run **fully offline** via the on-device Embedded
  Speech runtime: one **system-wide model** apps rely on, so nothing has to be
  bundled or downloaded per app (one install, one update path, shared by every
  app).
- Forced-HD on-device output is **near-identical to Microsoft's cloud neural
  voices**, not the old robotic local voices.
- Synthesis runs **on the CPU** (ONNX Runtime's default provider) **far faster
  than real time**, with no NPU or GPU. Measured: ~7 s wall / ~6.7 CPU-seconds to
  synthesize ~120 s of audio (about one core, RTF ≈ 0.06), with no NPU/GPU
  engaged, so it runs live on **virtually any modern x64 or ARM64 PC.**

The capability ships on every Windows machine. The public API to enumerate,
load, and drive it does not, so no app can build on it.

### Microsoft won't even use its own local tech

The clearest proof the gap is real: Microsoft's own products pay the cloud for
what the device could do for free.

- **Edge "Read Aloud"** streams its natural voices from the **cloud** (a network
  round-trip and server cost on every play), even though a same-class Natural HD
  voice now runs on the very same device, offline. It needs a connection, sends
  text off the device, and runs up a recurring cloud bill.
- **Clipchamp's** text-to-speech voiceover runs on **Azure** today, a per-use
  cloud cost for a feature the on-device HD voices could power for free, offline.

If Microsoft's own browser and video editor can't build on the local voice,
**no ISV can.** The tech is sitting idle behind a missing API. Innovation is
blocked at the source.

## WHAT: what local voices unlock

Open the API and the same on-device voice powers **new** products, and fixes
ones Microsoft **already** ships.

### Flagship: subtitles → live, multilingual voiceover

Every professional video already ships subtitles. Turn that track into an
on-device spoken voiceover, in the viewer's language, in sync with the video.

- **Proof:** the "Zava Dental" product video, voiced in **English (Ava)** and
  **French (Remy)**, Natural HD, fully offline. Same pipeline, only the subtitle
  language differs.
- A **WinUI app** plays the muted video and switches voiceover language **live,
  mid-play**, on the device.
- **Honest boundary:** no lip-sync, one voice per language, neutral delivery.
  This complements studio dubbing; it doesn't replace it. It's transformative for
  the vast middle: training, docs, demos, news, corporate comms, education, UGC,
  and accessibility.

### It scales the right way (bandwidth + accessibility)

Per-language cost for a ~2-minute clip, from the real assets:

| Asset (per language) | Size |
|---|---|
| Subtitle track (`.srt`) | **~2.6 KB** |
| Pre-rendered dub audio (AAC) | **~1.0 MB** |
| The video (sent once, all languages) | 116 MB |

- **~400× smaller** as a subtitle than as pre-rendered dub audio, per language.
- Subtitles are **already on the wire** for captions → the voiceover is
  **effectively free bandwidth**.
- 7 languages: **~18 KB of subtitles vs ~7 MB of dub audio**, versus **~812 MB** of
  duplicate dubbed video files.
- **One asset serves both** captions (deaf/HoH) and spoken narration (low-vision,
  dyslexic, eyes-busy, learners), and reaches the **long tail** of languages no
  studio would fund a voice cast for.

### Fix what already ships: the same voice, in every app

- **Edge Read Aloud → local:** same HD quality with **zero cloud cost**, offline,
  private, and instant, with no round-trip.
- **Clipchamp voiceover → local:** move its TTS off Azure and the cloud bill goes
  to zero, working offline.
- **Teams & Office:** on-device narration, captions read aloud, and accessible
  documents, with no per-minute bill.
- **Accessibility tools:** private, offline screen narration in the user's
  language, so nothing leaves the machine.

### A new creative surface: make every PowerPoint a video studio

Give PowerPoint the local voice API and **every deck becomes a narrated video**:

- **Speaker notes become the narration script**, one per slide.
- Render the deck to a **fully narrated MP4**, on the device.
- **One deck → many languages**, no re-recording.
- **Offline, private, and free**, with an Azure upsell for avatars and premium.

This turns each deck into a video production environment **built into the tool**,
rather than a per-minute cloud service (e.g. **Synthesia**) where the script and
content leave the org to render. Even this deck could narrate itself.

### Proof it's real: fast enough to switch language mid-video

| Metric | Result |
|---|---|
| Real-time factor (synthesis) | **≈ 0.025–0.05** (~20–40× faster than playback) |
| Steady-state synth (≈4 s of speech) | **~100 ms** per sentence |
| Time-to-first-audio (cold) | **~1.9 s** (one-time on load) |
| Load a **second** voice (staging cached) | **~23 ms** (essentially free) |
| First synth per voice (one-time warm-up) | ~1.1–1.4 s |

Pre-load the offered languages once → switching is **instant**: change the
dropdown and the next line speaks in the new language.

## HOW: make the POC real by removing the hack and shipping the API

### Today it works, but only as a hack

To reach the on-device HD runtime with no public API, this reference
implementation has to:

- Pass an **undocumented Embedded Speech license string** to unlock synthesis.
- Load **gated extension DLLs** out of a first-party SystemApps folder.
- Resolve native dependencies by **walking the package graph by hand**.

It's **unsupported and fragile**, exactly the friction that stops real products
from shipping on the capability. That's what a public API removes.

### The design: one API, local by default, cloud when you want it

| DEFAULT: on-device | UPSELL: same API + your Azure creds |
|---|---|
| Offline, private, free, instant | More voices, more languages, server-side scale |
| Runs on the installed Natural HD voice | Batch, streaming, cross-device workloads |
| No key, no bill, nothing leaves the device | Same code path; credentials switch the backend |

**Local is the free on-ramp; Azure is the upsell.** Apple has no cloud to
graduate to; Windows + Azure is a funnel only Microsoft can offer.

### The ask to Microsoft

This repo is a working reference implementation of what the API should look like.
Take the hack out; make it supported:

- Enumerate installed Natural voices (locale, gender, package).
- Load a voice and synthesize offline through the on-device HD runtime.
- Stream synthesis live to the speaker with word-boundary events.
- Same surface scales to Azure with credentials, so it's **local-first and
  cloud-optional.**

**Ship this as a first-class, supported Windows API**, and every app (Edge,
Clipchamp, Teams, Office, PowerPoint, media players, and accessibility tools)
gets instant, private, multilingual, on-device narration for free. It uses one
shared OS model with no per-app download, and comes with a paved road to Azure.

## What's in this repo

- **`WindowsNaturalVoices`**: the library, providing a voice catalog and
  `EmbeddedVoiceSpeaker` (forced-HD, offline, live playback).
- **`samples/SpeakWebPage`**: reads any web page aloud live (reader-mode
  extraction).
- **`samples/SpeakSubtitles`**: turns a subtitle file into a timeline-aligned
  voiceover track (the localization pipeline).
- **`samples/VideoVoiceover`**: a WinUI app that plays a muted video, lets you
  pick a language, plays the live on-device voiceover, and switches languages
  while it plays.
- **`docs/pitch/`**: this pitch (`live-voiceover.md`) and the reproducible deck
  (`build_deck.py` → `live-voiceover.pptx`).
